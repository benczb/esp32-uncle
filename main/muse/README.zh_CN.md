# 官方 Muse 配对核心

这些非界面文件改编自 [FalkoWing/muse-passport](https://github.com/FalkoWing/muse-passport)，提交 `664f5c2a3c9fb9c0b0bf4ed9801907c7f01fdb3e`，遵循随附的 Apache-2.0 [许可证](LICENSE)，保留原有版权声明。

移植保留上游加密配置协议和设备身份格式；移除工厂测试命令，将配置隔离存放在现有 `profile` 分区的 `muse` 命名空间中，不嵌入开发者 SDK token。ESP32-C3 移植使用上游社区 v5 身份验证，不冒充厂商证明；适配 ESP-IDF 5.5 提供的公开 Mbed TLS GCM 头文件，不写入 eFuse。未复制上游界面、字体、头像或板级驱动。

本集成尚在开发中，正式固件暂未启用。Android 转发验收、资源共存及聊天/语音仍需集成和实机验证。

`tests/muse_pairing/` 中的上游适配测试保留原有版权声明并遵循同一许可证，覆盖共享 v5 向量、存储失败与隔离、签名策略及使用真实主机加密库的社区握手（确认、重放、过期和会话绑定）。独立的 C3 编译探针已链接蓝牙配对核心，但它不是可交付的超级应用固件。

抽取的 Android 传输层保留上游经过认证的 GATT 帧、token 轮换、有界请求和 IMA-ADPCM 麦克风上传；协商原版 `opus-16000-60-v1` 助手语音播报，同时保留文字回复。应用刷新回调由可选的超级应用适配器提供，核心不访问 LVGL。仅供编译的探针没有用户界面，严禁刷入 Passport。便携编码器已与官方 Android `AudioUpload` 实现交叉验证，覆盖采样时长和缺失音频块拒绝。

转发层启动在内存不足时返回可重试的失败，不再中止设备；返回前释放已创建的队列、信号量和任务。初始化必须在注册蓝牙回调之前串行执行。主机故障注入覆盖每个启动分配及任务创建失败，并验证成功重试；这不代表已通过运行时配对或蓝牙验收。

蓝牙服务启动也会检查 NimBLE 返回值、所有应用服务注册、设备名称设置和主机任务创建结果。ESP-IDF 5.5 的 FreeRTOS 便捷封装会忽略任务创建失败，因此应用直接管理该主机任务。启动失败时释放互斥量并反初始化已建立的协议栈，再允许重试；如果协议栈回滚本身失败，则拒绝再次启动，直到重启。这不代表已验证 SDK 内部故障处理、射频行为或 Android 配对。

`setup_controller` 适配官方回调：设备信息、加密实体按键确认、Wi-Fi 扫描与连接钩子及账户配置。按键只排队保存提示时的会话版本，工作任务在配对锁内仅确认该会话。凭据写入及完成标记使用绑定会话的提交；过期的 Wi-Fi 或 token 结果不能写入凭据。可选的旧版 token 换取由应用钩子提供，临时 token 释放前清零；新版设备 token 对可直接接收。此控制器暂未连接 OTA 和远程解绑回调。下文所述的可选应用适配器已提供当前网络钩子与确认/配对码界面，语音传输另见下文，Android 实机听音仍需验收。本地编译探针使用始终失败的 Wi-Fi 钩子，仍严禁刷机。

配对初始化在启动 BLE 前返回可检查的结果。互斥锁分配或 P-256 曲线加载失败时拒绝启动配对并支持重试；真实加密库主机测试在成功握手前分别注入这两种失败。

可选应用适配器 `main/passport_muse.c` 现在会在打开 Muse 后由现有网络工作任务启动配对，
把实体确定键确认排队处理，并在独立的超级应用界面显示 Android 蓝牙配对码。
启动前等待非活动头像内存释放，不分配未使用的聊天缓存，也不轮询旧 Muse HTTP 路线；
退出页面后保持蓝牙服务运行。手机选择 Passport 当前已连接的 Wi-Fi；
如需换网，先在超级应用设置中操作，不引入第二套 Wi-Fi 管理器。

普通构建仍关闭 `CONFIG_PASSPORT_MUSE_BLE`。实验构建需要 NimBLE、持久化绑定和
Secure Connections。主机测试覆盖启动失败/重试、广播、复用当前网络、实体确认、
配对码、绑定恢复与延迟释放头像；排版测试覆盖中英文、两套主题的配对界面。
完整超级应用的蓝牙启用版本已编译通过，但实机内存共存、真实 Android 配对和聊天/语音
仍未验证。请勿将此实验配对适配器描述为已完成的 Muse 助手。

实验语音路径现在把长按下键/松开发送接到 BSP 麦克风和官方 Android IMA-ADPCM 上传。
音频仍由现有音频工作任务处理，录音期间网络工作任务暂停新请求。转发使用有界的
16 kHz 单声道录音，在提交最后一帧前读取聊天历史游标，再用确认的语音消息 ID
匹配已经完成的助手回复。离开 Muse 会取消打开的请求并释放响应缓存；旧回调版本
不能更新替代录音。

直接编译固件源码的主机测试覆盖麦克风到回复的路径、提前松开、取消未提交录音、
编解码器失败、非活动页面清理、分片响应、分配/发送错误、过长/无效回复、超时及
一千次取消/替换操作。这验证本地状态机行为，不代表真实 Muse 服务已通过。
默认启用前仍需完成 Android 配对、麦克风/转发实测及 SRAM/栈共存检查。
尚未实现从手机设置页输入 Muse 文字；回复音频通过官方伴侣播放。

设备回复缓存最多保留 6,399 字节 UTF-8 文字，更长的回复请在 Muse 手机应用查看。
现支持官方伴侣的 Opus 回复语音。

超级应用将 `phone_audio` 任务栈由上游的 4 KB 调整为 6 KB。已配对设备在开始录音时，
4 KB 工作任务触发了栈保护重启。此集成调整不改变蓝牙协议、SDK token 持久化方式，
也不修改单独保存的上游仓库。

Muse 录音期间，超级应用释放上一轮 6,400 字节回复缓冲，改用固定 320 字节状态缓冲。
麦克风 DMA 释放、助手文字到达后，才重新分配回复缓冲，为蓝牙控制器保留更多可用内存。
此调整不缩减上游音频队列，也不改变传输格式。

回复音频沿用上游有界语音缓冲和 `components/passport_opus` 中的定点 Opus 1.6.1 源码，保留 BSD 许可证。语音控制帧由 BLE 工作任务发送，I2S 仅由语音任务写入。上游独立仓库保持不变。完成一轮对话后释放历史缓冲和录音工作任务，再请求伴侣音频；解码器和播放任务仅在朗读期间存在。期间释放原始公共数据缓存，已显示天气保持可见，播放结束后恢复联网服务。音量面板沿用应用字体，与长按下键录音分开。

Muse 朗读时网络工作任务退出，先释放 8 KB 栈，再启动原版 24 KB 解码任务。主循环在播放结束或取消后重启网络任务，Wi-Fi 与蓝牙仍保持连接。保留上游解码栈大小，不增加常驻任务。释放公共数据缓存时同步重置到期时间，返回巴士功能可立即刷新。

历史请求沿用上游的内存分配策略：开始时不预留整块响应缓冲，仅随已接收字节增长，仍受原有 8 KB 上限约束。请求等待与超时状态不依赖是否已接收正文。语音消息确认后，先等待上传任务及队列退出，再轮询回复，避免完整历史预留与录音上传资源同时占用。内存分配失败与响应过大仍分别报告。
